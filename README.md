# conform-desktop

[English](README.en.md)

Приложение приводит аудиодорожки к таймлайну заданного видеофайла. На вход — референс
(файл, задающий таймлайн) и любое число исходных файлов с аудиодорожками. На выходе —
дорожки FLAC, синхронные референсу, готовые к сборке в контейнер.

Параметров подгонки нет: какие поправки нужны конкретной дорожке, определяется
измерениями.

---

# Установка на Windows

Нужно: Windows 10 или 11 (x64), 4.6 ГБ под установку и около 8 ГБ под промежуточные
файлы обработки. Видеокарта NVIDIA желательна; без неё выполняется тот же путь обработки
на процессоре — дольше, результат тот же. Права администратора не нужны.

### Шаг 1. Создайте папку для приложения

Например `D:\conform`. Установка развернётся внутри неё, в системные каталоги ничего не
пишется.

### Шаг 2. Скачайте загрузчик

Со страницы [Releases](../../releases) — файл `conform-setup.exe` (13 МБ). Положите его в
созданную папку.

### Шаг 3. Запустите загрузчик и нажмите «Установить»

Откроется окно со списком компонентов. Загрузчик скачает их (около 1.5 ГБ), сверит
контрольные суммы и распакует.

**Если скачивать через приложение неудобно** (медленный канал, нет доступа), скачайте
файлы заранее любым способом — браузером, менеджером загрузок, с другого компьютера:

1. со страницы Releases возьмите `manifest.json` и три архива `conform-*.7z`;
2. создайте рядом с `conform-setup.exe` папку `packages` и положите файлы туда;
3. запустите загрузчик, нажмите «Проверить наличие файлов», затем «Установить».

Сеть в этом случае не нужна. Файлы распознаются по контрольной сумме, поэтому
переименование при передаче не мешает.

### Шаг 4. Дождитесь проверки установки

После распаковки загрузчик прогоняет контрольный материал через полный конвейер
обработки и сверяет контрольную сумму результата с эталонной. В журнале должно появиться:

```
Результат обработки совпал с эталонным: установка исправна.
```

Так проверяется работоспособность, а не наличие файлов: неполная распаковка или
несовместимый набор библиотек выявляются именно здесь.

### Шаг 5. Нажмите «Запустить»

Откроется окно приложения. В дальнейшем запускать можно как загрузчиком, так и напрямую —
`app\conform-desktop.exe`.

### Что скачивается

| Компонент | Что внутри | Архив |
|---|---|---|
| `conform-runtime` | Вычислительный рантайм: torch, библиотеки CUDA | 1199 МБ |
| `conform-app` | Приложение, интерфейс, ядро обработки | 254 МБ |
| `conform-ffmpeg` | Декодер медиафайлов | 109 МБ |

### Обновление

Скачайте `conform-setup.exe` нового выпуска и запустите **в той же папке**. Он сверит
установленное с составом нового выпуска и скачает только изменившееся: обычно это
`conform-app` (254 МБ), рантайм и декодер остаются на месте.

# Запуск на Linux

Готового дистрибутива для Linux пока нет — запуск из исходников. Проверено на Ubuntu 24.04
с CUDA.

### Шаг 1. Системные пакеты

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip ffmpeg \
    libgl1 libegl1 libxkbcommon0 libxkbfile1 libxcb-cursor0 libnss3 libnspr4 \
    libasound2t64 libxdamage1 libxrandr2 libxcomposite1 libxtst6 libgbm1 \
    libcups2t64 libdrm2 libpango-1.0-0 libatk1.0-0t64 libatk-bridge2.0-0t64 \
    libatspi2.0-0t64 libgl1-mesa-dri
```

### Шаг 2. Окружение Python

```bash
git clone https://github.com/wolfram0108/conform-desktop.git
cd conform-desktop
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

Проверка, что видеокарта доступна:

```bash
.venv/bin/python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Ответ `False` не является ошибкой — обработка пойдёт на процессоре.

### Шаг 3. Запуск с окном

```bash
export PYTHONPATH="$PWD:$PWD/src"
export TM_FFMPEG=/usr/bin/ffmpeg TM_FFPROBE=/usr/bin/ffprobe
.venv/bin/python -m ui
```

### Шаг 4. Запуск без графической сессии

По ssh или на машине без дисплея окно создать нельзя, но приложение может работать как
локальный сервис — интерфейс открывается браузером:

```bash
export PYTHONPATH="$PWD:$PWD/src"
export TM_FFMPEG=/usr/bin/ffmpeg TM_FFPROBE=/usr/bin/ffprobe
export QT_QPA_PLATFORM=offscreen LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe
export QTWEBENGINE_CHROMIUM_FLAGS='--no-sandbox --disable-gpu --single-process'
.venv/bin/python -m ui
```

Затем откройте `http://127.0.0.1:8799/app/index.html`.

Переменные обязательны: без программного OpenGL встроенный движок страницы завершает
работу на создании графического контекста. Флаг `--no-sandbox` нужен только при запуске
от `root`.

# Первая задача

1. Вкладка **Задача**, поле **Референс** — выберите файл, задающий таймлайн. Если в нём
   несколько аудиодорожек, укажите, какая из них служит звуковым эталоном.
2. **Исходные файлы** — добавьте файлы кнопкой или перетаскиванием. Для каждого отметьте
   аудиодорожки, которые нужно обработать. Годятся и файлы без видеоряда — обычные
   аудиофайлы.
3. **Выходной каталог** — куда складывать результат.
4. **Добавить в очередь**. Если включено «запускать сразу», обработка начнётся немедленно;
   иначе задача ждёт запуска кнопкой ▶.
5. Вкладка **Очередь** — ход выполнения. Стрелка слева от названия раскрывает подробности:
   операции с их длительностью, дорожки с показателями, графики, кнопка перехода к файлам.

Результат — файлы FLAC в выходном каталоге; раскладка каналов исходной дорожки
сохраняется (2.0, 5.1, 7.1).

# Что показывают измерения

Для каждой обработанной дорожки приводятся:

| Показатель | Смысл | На что смотреть |
|---|---|---|
| остаточное рассогласование | Смещение звука после обработки | Норма — единицы миллисекунд |
| покрытие измерением | Доля длительности, где звуковой анализ имел опору | Низкое значение означает, что у файлов мало общего звука |
| сопоставлено | Доля кадров, получивших соответствие | Малая доля — источник не соответствует референсу |
| сходство кадров | Близость признаков сопоставленных кадров | Низкое при сильном пережатии источника |
| разрывы | Число скачков таймлайна и величина наибольшего | Соответствуют вставкам и вырезам |
| заполнено референсом | Длительность участков, заполненных звуком референса | Участки, где у источника звука нет |

Значения вне ожидаемого диапазона помечаются как требующие проверки. Отказ одной дорожки
не останавливает задачу: остальные обрабатываются, причина отказа показывается при своей
дорожке.

Замер производительности на RTX 4090: референс 1080p длительностью 23 минуты и одна
дорожка — 2 минуты 34 секунды.

# Как это работает

Обработка идёт двумя уровнями измерения.

**Соответствие по кадрам** задаёт структуру. Для каждого кадра вычисляется дескриптор,
кадры референса и источника сопоставляются в полосе поиска; из результата восстанавливается
ход времени (включая ускорение PAL) и границы вставок и вырезов. Если сопоставлению мешает
кадрирование или масштабирование, оценивается преобразование кадра и признаки
пересчитываются.

**Уточнение по звуку** работает поверх уже уложенного потока и находит то, чего в
изображении нет: остаточное смещение, дрейф, локальные разрывы — следы пересведения, иной
редакции фонограммы, дефектов исходника. Участки тишины, где референс звучит, заполняются
синхронным звуком референса.

Порядок операций детерминирован. Необязательна только геометрическая коррекция — она
выполняется, когда грубое сопоставление не дало результата.

# Ограничения

* Расхождение изображения и звука, допущенное при сведении самого источника, не
  устраняется: относительно референса это не рассинхронизация, и приложение помечает такой
  случай как дефект источника.
* Нелинейное изменение темпа звука без соответствующего изменения видеоряда звуковым
  уровнем не снимается.
* Для источника без видеоряда доступно только звуковое уточнение, поэтому структурные
  расхождения на таком материале не восстанавливаются.
